# 开始创作：从打开文件到写出第一章

> 面向"我要马上开始写小说"的使用者。环境安装细节见 [环境搭建与开发指南](环境搭建与开发指南.md)。
> **Windows 用户建议先看 [Windows首次使用清单](Windows首次使用清单.md)**（装软件 → 自检 → 双击启动 → 配模型 → 备份，逐屏对照）。
> 界面文案以当前版本（中文界面）为准。

---

## 第 0 步：打开哪个文件

在项目根目录，按你的系统双击对应文件：

| 系统 | 打开这个文件 | 说明 |
| --- | --- | --- |
| **Windows** | **`开始创作.bat`** | 双击即可，会弹出一个命令行窗口持续运行；**关掉窗口 = 停止服务** |
| **macOS** | **`开始创作.command`** | 在 Finder 里双击；首次如被拦截，去"系统设置 → 隐私与安全性 → 仍要打开" |
| **Linux** | **`开始创作.sh`** | 双击或 `./开始创作.sh` |

它会自动完成这些事（首次约 2~5 分钟，之后十几秒）：

1. 检查 Python / Node / Docker；
2. 用 Docker 启动 MongoDB 8.0 单节点**副本集**，首次自动 `rs.initiate` 并等待可写主节点；
3. 缺依赖就装（`.venv`、`node_modules`），缺前端产物就构建；
4. 起后端 `127.0.0.1:8200`、前端 `127.0.0.1:3300`；
5. **自动打开浏览器**到 `http://127.0.0.1:3300`；
6. 把数据库地址写进 `user_data/config/config.yaml`（之后用 `start.bat` 桌面启动器也能直接跑）。

> 前提：**Docker Desktop 已启动**（鲸鱼图标变绿）。没有 Docker 就要自己准备一个副本集，用
> `python scripts/quickstart.py --no-mongo --mongo-uri "你的连接串"` 启动。
>
> 换端口：`开始创作.bat --backend-port 8300 --frontend-port 3400`。
> 开发调试：`python scripts/quickstart.py --dev`（后端热重载 + `next dev`）。

## 第 1 步：配置模型（只能配一次，之后一直用）

打开界面后进 **设置**：

1. **LLM Provider 管理 → 新增 Provider**
   - **服务类型**：`openai` / `deepseek` / `gemini` / `claude`（选你手上有 Key 的那家；兼容自建网关一般选 `openai`）
   - **接口地址**：官方地址留空或填官方域名；中转/自建网关填它的 base url
   - **API Key**：粘贴你的 Key（保存后界面只显示掩码）
   - **默认模型**：例如 `gpt-4o-mini`、`deepseek-chat`、`gemini-2.5-flash`
   - 保存后点 **测试**，通过再启用
2. **小说生成流程配置**：把 **全局默认 Provider** 选成刚配的那个，保存。
   （想省钱/分流，可以在这里给单个流程步骤单独指定别的 Provider。）
3. 回 **设置 → 数据库配置** 确认连接是绿色的。"替换连接"里应该是：
   `mongodb://127.0.0.1:27017/?replicaSet=rs0&directConnection=true`，库名 `novel_generator`。

> 提示：测试和生成都会真实调用模型并计费；`max_concurrency` 调低可以避免 429。

## 第 2 步：新建小说

首页 **新建小说** → 输入一两句创意（例："一个能听见潮汐记忆的档案管理员，在填海城市里追查失踪的姐姐"）
→ 选故事方向 → 逐层生成并确认：**扩写完整剧情 → 提炼创意 → 生成故事核心 → 生成小说设定**。
每一步都能改，确认后保存。

---

## 第 3 步：跟着左侧「创作进度」一路往下

界面把整个流程做成了可勾选的进度条，**卡住时看它提示的"下一步"就行**：

| 阶段 | 你要做的事 | 备注 |
| --- | --- | --- |
| **建立作品** | 保存小说资料（故事方向、世界观、风格、篇幅） | AI 可生成，也可手写 |
| **开场资料** | 核心势力 → 势力关系 → 主角 → 核心角色 → 势力归属 → 角色关系 | 关系可以在**关系图谱**里看 |
| 　 | 开场世界规则、开场重要物品 | **可选**，点"暂不添加，继续" |
| **本卷剧情** | 准备第一卷 → 生成全书分卷 → 完善本卷剧情 | 卷可以多卷，先做第一卷 |
| 　 | 确认本卷出场的势力 / 人物计划 / 地点 | 可手工增删 |
| **本卷准备** | 篇章计划 → 场景计划 → 章计划 | 逐层细化，每层都能改 |
| **本卷章节** | 准备下一章剧情 → **写作·章节 N** | 生成正文 → 审阅候选 → 保存 |
| **检查或继续规划** | 章后记录（人物/关系/物品/规则的变化核对）、伏笔、继续下一章 | 章后记录帮助长线不失忆 |

要点：

- **一切生成结果都是"候选"**：先审阅、可编辑，再点保存，不会直接覆盖已有内容。
- **正文可以纯手写**：章节编辑区支持直接写、字数统计、草稿导出、历史版本。
- **未保存的草稿**存在浏览器 localStorage（换浏览器/清缓存会丢），重要内容及时保存或导出。
- 关系图谱、伏笔、角色卡/地点卡/势力卡/物品卡/规则卡都在左侧栏，随时回看与修改。

## 第 4 步：日常使用与数据安全

- 每天开工：双击 `开始创作.bat`（或 `start.bat` 桌面启动器）→ 浏览器打开 → 继续。
- 收工：关闭命令行窗口/启动器即停服务；**MongoDB 由 Docker 单独管理**，
  停它用 `docker compose -f compose.mongodb.yaml stop`，**不要加 `-v`**（会删数据卷）。
- 备份（重要！）：MongoDB 数据库 + `user_data/` 目录**一起**备份，只导出单本书不算完整备份。
- 这是本机应用，**没有登录鉴权**，自带 MongoDB 也没密码，**不要暴露到公网**。

## 常见卡点速查

| 现象 | 处理 |
| --- | --- |
| 双击后窗口一闪而过 | 用命令行运行同一文件看报错：`python scripts/quickstart.py` |
| 提示 Docker 未运行 | 先启动 Docker Desktop，等图标变绿再双击 |
| 27017 被占用 | 本机已有别的 MongoDB：别混用，改用 `--mongo-uri` 指到你自己的副本集 |
| 界面提示"请先配置数据库" | 数据库没起或地址不对：`docker compose -f compose.mongodb.yaml ps` 看 healthy |
| 保存时报事务错误 | 连的是**单机 mongod**，不是副本集；必须 `--replSet rs0` 且已 `rs.initiate` |
| 生成报"没有可用的 AI 服务" | 设置里的 Provider 没启用，或全局默认 Provider 没选 |
| 端口冲突 | `开始创作.bat --backend-port 8300 --frontend-port 3400` |
| 同一目录开了两个实例 | 会报"这个数据目录正在使用"，关掉多余实例 |
