## 1. 一句话结论：需要装什么

| 软件 | 版本要求 | 作用 | 是否必须 |
| --- | --- | --- | --- |
| **Git** | 任意较新版本 | 拉代码、版本管理 | 必须 |
| **Python** | **3.13 推荐，最低 3.12** | 后端 FastAPI + 桌面启动器 | 必须 |
| **Node.js + npm** | **Node 24 推荐，最低 20.9** | 前端 Next.js 16 | 必须 |
| **MongoDB 8.0（副本集）** | 必须能跑**多文档事务**（replica set） | 存小说/角色/正文等业务数据 | 必须 |
| **Docker Desktop**（或等价容器运行时） | 最新稳定版 | 最省事地跑上一条的 MongoDB | 强烈推荐 |
| 代码编辑器（VS Code / PyCharm） | — | 开发 | 建议 |
| MongoDB Compass / `mongosh` | 与 MongoDB 8.0 匹配 | 查数据、排障 | 建议 |
| Python 依赖（`requirements.txt`） | 见第 7 节 | FastAPI、PyMongo、openai/gemini/claude SDK、PySide6 等 | 必须 |
| 前端依赖（`package.json`） | 见第 7 节 | Next.js 16、React 19、HeroUI、React Flow | 必须 |
| 一个可用的 LLM 服务 | OpenAI / Gemini / Claude / DeepSeek 或兼容自建网关 | AI 生成功能（不配也能手写） | 按需 |

**关键点（很多人第一次装失败就在这里）**

1. **Python 必须是 3.12 及以上**。代码里用了 `Path.is_junction()`（`backend/migrations/__init__.py`），Python 3.11 会直接 `AttributeError` 崩溃。官方文档推荐 3.13。
2. **MongoDB 必须是副本集（replica set）**，单机 `mongod` 无法做保存（多文档事务），会报事务相关错误。项目自带 `compose.mongodb.yaml` 帮你起单节点副本集 `rs0`。
3. **前端要求 Node ≥ 20.9**（Next.js 16 + React 19 的硬性要求）。
4. **端口**：后端 `8200`、前端 `3300`、MongoDB `27017`。三个端口不要被别的程序占用。
5. **本机应用，无登录鉴权**，自带 MongoDB 没有密码且只绑定回环地址，**不要直接暴露到公网**。

## 3. 安装步骤 A：Windows（官方主线，最省心）

### 3.1 装四件套

1. **Python 3.13**：<https://www.python.org/downloads/windows/> 下载 3.13.x 安装包，安装时**勾选 `Add python.exe to PATH`**。
2. **Node.js 24 LTS**：<https://nodejs.org/en/download> 下载 `.msi` 安装。
3. **Git for Windows**：<https://git-scm.com/download/win>，安装时把 **"Git Bash"** 和 **"Use Git from the Windows Command Prompt"** 都选上。
4. **Docker Desktop**：<https://docs.docker.com/desktop/setup/install/windows-install/>，装完**启动并等到鲸鱼图标变绿**（需要启用 WSL2 后端；Windows 家庭版也会自动装 WSL2）。

校验（PowerShell 新开一个窗口）：

```powershell
python --version      # 期望 Python 3.13.x
node --version        # 期望 v24.x（>= v20.9 即可）
npm --version
git --version
docker compose version
```

### 3.2 拉代码 + 装依赖

```powershell
cd D:\dev
git clone https://github.com/YILING0013/AI_NovelGenerator.git
cd AI_NovelGenerator

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

cd frontend
npm ci
cd ..
```

> Windows 上 `python -m venv` 报"无法创建符号链接/权限错误"时，用**管理员** PowerShell 再执行一次即可（或在"设置 → 开发者选项 → 允许开发人员模式"打开）。

### 3.3 起 MongoDB 副本集

```powershell
# 先确认 27017 没被占用
netstat -ano | findstr :27017

docker compose -f compose.mongodb.yaml up -d
docker compose -f compose.mongodb.yaml exec mongodb mongosh
```

**只有第一次使用全新数据卷时**，在 `mongosh` 里执行一次初始化：

```javascript
rs.initiate({ _id: "rs0", members: [{ _id: 0, host: "localhost:27017" }] })
exit()
```

回到 PowerShell 看健康状态，等 `healthy`：

```powershell
docker compose -f compose.mongodb.yaml ps
```

- 数据存放在 Docker 命名卷 `novel-generator-mongodb-data` / `novel-generator-mongodb-config` 里。
- **不要用 `docker compose ... down -v`**，`-v` 会删数据卷。停止用 `stop` 或 `down`（不带 `-v`）。
- 已经 `rs.initiate` 过的库**不要重复初始化**；显示 unhealthy 也不代表要清库。
- 你机器上如果已经有一个独立的 Windows 版 MongoDB，**不要和 Docker 这个混用**，也不要为了腾端口去删数据卷。

### 3.4 启动应用

双击根目录 **`start.bat`**（它会调用 `launcher.py` 弹出桌面启动器，用 `.venv` 起后端，并在首次启动或代码变化后自动构建前端）。

- `start.bat` **不会**帮你装依赖或装数据库，缺 `.venv` 时它会提示你按 3.2 装。
- 关闭启动器 = 停掉它启动的前后端；MongoDB 由 Docker 单独管理。
- 浏览器打开 **<http://127.0.0.1:3300>**。
- 端口冲突就在启动器里改端口（会写到 `user_data/config/launcher_settings.json`）。

### 3.5 在界面里配置数据库

进入 **设置 → 数据库配置** → "替换连接"，保存：

| 字段 | 值 |
| --- | --- |
| MongoDB URI | `mongodb://127.0.0.1:27017/?replicaSet=rs0&directConnection=true` |
| 数据库名 | `novel_generator` |

`mongo_transaction_mode` 保持默认 `required` 即可。检查通过后就能新建小说。

### 3.6 配置模型

**设置 → LLM Provider 管理**：填 服务类型（openai / deepseek / gemini / claude）、接口地址、API Key、模型名，启用并保存；
再到 **小说生成流程配置** 选全局默认 Provider 并保存。内置流程可以直接用，也能按节点单独指定模型。

> 接口必须兼容所选适配器（OpenAI Chat Completions / Responses、Gemini Generate Content / Interactions、Anthropic）。费用由服务商计收，生成一次可能调用多次模型。

## 4. 安装步骤 B：macOS / Linux（命令行）

```bash
# macOS: brew install python@3.13 node git
# Ubuntu/Debian: 用 deadsnakes 或 pyenv 装 3.13；Node 用 nvm 或 NodeSource
git clone https://github.com/YILING0013/AI_NovelGenerator.git
cd AI_NovelGenerator

python3.13 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt

cd frontend && npm ci && cd ..

# MongoDB 副本集（Docker 方式，和 Windows 相同）
docker compose -f compose.mongodb.yaml up -d
docker compose -f compose.mongodb.yaml exec mongodb mongosh
#   → rs.initiate({ _id: "rs0", members: [{ _id: 0, host: "localhost:27017" }] })
#   → exit()
```

启动后端：

```bash
.venv/bin/python main.py          # 默认 127.0.0.1:8200
```

启动前端（另开一个终端）：

```bash
cd frontend
export NEXT_PUBLIC_API_BASE="http://127.0.0.1:8200"   # 必须在 build 之前设置
npm run build
npm run start -- --hostname 127.0.0.1 --port 3300
```

macOS/Linux 没有图形启动器时**不要用 `launcher.py`**（它依赖 PySide6 的桌面窗口，无桌面会话会失败），直接用上面的命令。
也可以写个 `scripts/dev_local.sh`（本仓库已附带）一条命令做完检查+启动。

## 5. 开发模式（日常写代码用这套）

打开两个终端，都在项目根目录：

```bash
# 终端 1：后端热重载（改 py 文件自动重启）
.venv/bin/uvicorn backend.app:app --host 127.0.0.1 --port 8200 --reload
#   Windows: .\.venv\Scripts\uvicorn.exe backend.app:app --host 127.0.0.1 --port 8200 --reload

# 终端 2：前端 dev 模式（热更新，不用每次 build）
cd frontend
# 前端默认就请求 http://localhost:8200，所以本地开发可以不设 NEXT_PUBLIC_API_BASE
npm run dev -- --hostname 127.0.0.1 --port 3300
```

要点：

- 打开 <http://127.0.0.1:3300>；接口文档 <http://127.0.0.1:8200/docs>、OpenAPI <http://127.0.0.1:8200/openapi.json>。
- **`NEXT_PUBLIC_API_BASE` 是构建期注入的**：改了它必须重新 `npm run build`（dev 模式重新 `npm run dev`）。默认值写死在 `frontend/src/lib/api.ts`：`http://localhost:8200`。
- 后端 CORS 白名单按"前端端口"生成（`http://127.0.0.1:{前端端口}` 与 `http://localhost:{前端端口}`）。换前端端口时，后端和前端**两边都要设 `NOVEL_GENERATOR_FRONTEND_PORT`**，否则浏览器会报 CORS 错误。
- 想看详细日志：`NOVEL_GENERATOR_BACKEND_DEBUG=1`（Windows：`$env:NOVEL_GENERATOR_BACKEND_DEBUG="1"`）。
- 生产模式构建：`cd frontend && npm run build`，产物在 `frontend/.next`；可用 `NEXT_DIST_DIR` 指定别的构建目录，避免覆盖正在跑的服务产物。
- 代码风格：后端全部中文 docstring（每个函数都写 功能/Args/Returns），前端 TypeScript 严格模式；提交前建议 `cd frontend && npm run lint`。贡献流程见 `.github/CONTRIBUTING.md`。

### 5.1 目录导览（改代码前先看这里）

## 6. 环境变量一览

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `NOVEL_GENERATOR_BACKEND_PORT` | `8200` | 后端监听端口 |
| `NOVEL_GENERATOR_FRONTEND_PORT` | `3300` | 仅用于生成 CORS 白名单，需与前端实际端口一致 |
| `NOVEL_GENERATOR_BACKEND_DEBUG` | 关闭 | `1` 打开后端调试日志 |
| `NOVEL_GENERATOR_MONGODB_URL` | 读 `user_data/config/config.yaml` | 进程级覆盖 MongoDB URI（不写回用户配置） |
| `NOVEL_GENERATOR_MONGO_DATABASE_NAME` | 同上 | 进程级覆盖数据库名 |
| `NOVEL_GENERATOR_USER_DATA_DIR` | 项目下 `user_data/` | 用户数据根目录（配置、导出、上传封面、备份） |
| `NEXT_PUBLIC_API_BASE` | `http://localhost:8200` | 前端请求的后端地址，**构建期**生效 |
| `NEXT_DIST_DIR` | `.next` | Next 构建输出目录 |

数据放在哪（备份时逐项照顾到）：

| 数据 | 位置 |
| --- | --- |
| 小说/角色/规划/正文/写作记录 | MongoDB（配置里指定的库） |
| 数据库与模型配置（含密钥） | `user_data/config/config.yaml` |
| 自定义流程、上传封面 | `user_data/task_flows/`、`user_data/static/` |
| 导出、迁移备份、迁移记录 | `user_data/exports/`、`user_data/backups/`、`user_data/migrations/` |
| 启动器端口设置 | `user_data/config/launcher_settings.json` |
| 未保存的正文草稿 | 当前浏览器 localStorage |

MongoDB 与 `user_data/` 要**一起**备份；只导出单本书不是完整备份。升级前先停应用再备份。

## 8. 常见问题排查

| 现象 | 原因 / 解决 |
| --- | --- |
| 后端起不来，`AttributeError: 'PosixPath' object has no attribute 'is_junction'` | Python < 3.12。装 3.13 并重建 venv：`rm -rf .venv && python3.13 -m venv .venv` |
| `npm ci` 报 `Missing: @swc/helpers@... from lock file` | 旧提交的锁文件不同步（本仓库已修复）。改用 `npm install` 或更新到本仓库最新代码 |
| 页面一直停在"请先在设置中配置数据库" | 数据库没配或连不上：检查 `docker compose ... ps` 是否 healthy、URI 是否带 `replicaSet=rs0&directConnection=true` |
| 保存时报事务相关错误 | 连的是**单机 mongod** 而不是副本集。必须 `--replSet rs0` 且 `rs.initiate` 过 |
| MongoDB 容器 unhealthy | 首次使用还没 `rs.initiate`；已有数据时不要清库，先在 `mongosh` 里 `rs.status()` 看主节点 |
| 前端报 CORS / 请求打不到后端 | 前端端口与后端 `NOVEL_GENERATOR_FRONTEND_PORT` 不一致；或 `NEXT_PUBLIC_API_BASE` 改完没重新构建 |
| `npm run dev` 起不来，提示 Node 版本过低 | 需要 Node ≥ 20.9（推荐 24） |
| 端口被占用 | 换端口（后端启动器/环境变量 + 前端 `--port`），别 kill 掉不确定的进程 |
| Windows 上 `start.bat` 一闪而过 | 缺 `.venv` 或缺 PySide6：按提示 `pip install -r requirements.txt`；把 `pythonw` 换成 `python` 跑 `launcher.py` 能看到报错 |
| 生成很慢 / 报 429 | 模型服务限流；同一 Provider 的 `max_concurrency` 在设置里调低 |
| 生成结果 JSON 解析失败 | 模型不支持 JSON Schema：在 provider 上关掉 `supports_json_schema`，或换模型/用 `structured_output_mode: tool_call` |
| 重装/升级后启动很慢 | 生产模式首次启动或前端代码变化后会重新构建前端（几十秒），属正常 |

## 9. 安全与使用提醒

- 这是**面向本机**的应用，没有面向公网的用户认证，自带 MongoDB 也没设密码且只绑 `127.0.0.1`。**不要 port-forward 到公网 / 不要部署到公网服务器**。
- AI 操作会把所需的故事上下文发送到你自己配置的模型服务，敏感内容请先评估。
- 模型调用按服务商计费；重试、流程多节点都会重复计费。
- 项目为 AGPL v3.0：二次分发/提供网络服务时要遵守其开源义务。
