# AI 小说生成器 · 全量分析与工作界面流设计

> 依据：本仓库 `arena/d5d2ac87-main`（上游 `YILING0013/AI_NovelGenerator` main 分支）。
> 数据来源均为实际代码与运行中的后端：`curl /openapi.json`（**310 个接口 / 258 条路径**）、

> 配套可点击原型：[工作界面流原型.html](工作界面流原型.html)

---

## 1. 一句话定位

它不是"输入一句话吐一本小说"的生成器，而是一个**把长篇小说拆成"设定 → 分卷 → 篇章 → 场景 → 章 → 正文 → 章后事实核查"七层，每层都由 AI 产出候选、由作者审阅保存的创作工作台**。
核心资产是：**跨章一致性**（人物/势力/物品/关系/规则的事实链）和 **可编辑的 AI 流程编排**。

技术栈：Next.js 16（App Router, React 19, HeroUI, React Flow, Tailwind 4）+ FastAPI（PyMongo 异步、MongoDB 副本集事务）+ PySide6 桌面启动器。前后端分离，后端默认 `127.0.0.1:8200`，前端 `3300`。

```
┌───────────────────────────────────▼───────────────────────────────────────────────┐
│                          后端 FastAPI (8200)  main.py → backend.app:app           │

│  services/llm/*               AI 服务：契约校验、候选、provider 测试、工作流        │
│  services/task_flows/*        流程引擎：节点图、执行、内置方案、预演(preview)       │
│  llm/*                        Provider 适配器：openai/deepseek·gemini·claude       │
│                               + JSON 守卫 + prompt 选择 + 流式                    │
│  db/*                         PyMongo Async + 事务 + 各集合 repository + 索引      │
│  migrations/*                 文件布局迁移、库结构准备、内置流程升级                │
└───────────────────────────────────┬───────────────────────────────────────────────┘
                                    │ replicaSet 事务
                            MongoDB 8.0（rs0）
                     ┌──────────────┴──────────────┐
              user_data/（配置、导出、备份、封面、自定义流程）
```

关键设计：
- **没有 ORM**，用 `db/repositories/*` 直接操作集合；写入走 `db/transaction.py`，需要副本集。
- **前端只做展示 + 草稿**，所有"是否完成"由后端从正式事实重算（见 §4 就绪门禁）。
- 每个写接口都带 `expected_version`（乐观锁），冲突返回 409，前端提示"已被其他会话修改"。

## 3. 数据模型（实体 + 关键字段）

层级：**Novel → Volume → Arc → Scene → Chapter**（严格四层，章节挂在场景下）。

| 实体 | 关键字段（节选） | 说明 |
| --- | --- | --- |
| **Novel** 小说 | title, subtitle, genre, tags, introduction, summary, core_seed, worldview, writing_style, narrative_pov, era_background, plot, tone, target_audience, core_idea, number_of_chapters, words_per_chapter, cover_image, status, version | 全书设定 + 篇幅预算 |
| **Volume** 卷 | title, subtitle, summary, goal, theme, `planning{premise, major_conflict, key_turning_points, start_state, end_state, target_chapter_count, target_word_count}`, order_index, version | 卷级剧情与目标 |
| **Arc** 篇章 | title, summary, `planning{goal, start_state, end_state, key_beats, continuity_notes, 目标字数/章数, character_ids, faction_ids, location_ids, item_ids, rule_ids}`, plot, plot_source_fingerprint | 篇章=一段连续冲突 |
| **Scene** 场景 | title, summary, planning（同上结构）, plot, order_index | 场景=一次时空连续的戏 |
| **Chapter** 章 | title, summary, `planning{goal, start_state, end_state, beats, pov_character_id, must_include, must_avoid, target_word_count}`, `content`（正文）, word_count, chapter_number | 正文与字数在这里 |
| **ChapterRevision** | 历史版本 | 正文历史版本/回滚 |
| **Character** 角色 | name, aliases, role_type, importance_level, gender, age_group, race, identity, appearance, personality, core_desire, core_fear, strengths, weaknesses, abilities, conflict_with_mainline, relationship_with_protagonist, status | 角色档案 |
| **CharacterFact** | 按故事位置（卷/篇章等）记录的角色状态 | 角色在故事不同位置的"事实" |
| **CharacterRelation** | source/target character, relation_type, current_state, intensity, 设计 vs 事实 | 关系有"设计"和"事实"两条线 |
| **CharacterFactionBinding** | character, faction, membership_type, role_title, public_status, loyalty_level, is_primary, is_active | 势力归属 |
| **Faction** 势力 | name, faction_type, positioning, public_stance, core_goal, hidden_goal, resources_and_advantages, organization_style, core_values, conflict_with_mainline, influence_scope, level/父级 | 支持层级结构 |
| **FactionRelation / FactionFact / FactionVolumeState** | 关系、事实、按卷状态 | 与角色同构 |
| **Location** 地点 | name, location_type, parent_location_id, description, environment, atmosphere, geography, rules_and_constraints, applicable_rule_ids, associated_faction_ids, story_function | 支持树形父子 |
| **Item** 物品 | name, item_type, description, origin, abilities, limitations, costs, owner_character_id, controlling_faction_id, current_location_id, lifecycle_status, story_function | 持有人可追溯 |
| **WorldRule** 规则 | name, category, statement, scope_type, scope_entity_ids, enforcement, exceptions[{condition,effect}], costs_and_consequences, priority | 规则可绑定适用范围 |
| **Foreshadowing** 伏笔 | title, content, target_effect, planting_position, resolution_position, `status`, planted_evidence, resolved_evidence | 埋/收位置 + 证据 |
| **ChapterEvent / ChapterReport** 章后记录 | title, content, `evidence{chapter_id, version, revision_id, content_hash, start, quote}`, related_entities, 确认/作废 | 事件与检查报告 |
| **EntityStateHistory** | before/after、evidence、confirmed_at、needs_review | 任何状态变更都留痕 |
| **TaskFlow** 流程方案 | task, 节点图(nodes/edges/control_edges/subflows), 输入输出端口、prompt、provider、revision | 可编辑的 AI 编排 |
| **GenerationRecord / Candidate** | 每次生成的输入、候选、采用结果 | 可复现、可重试 |

三个贯穿全项目的机制：
1. **候选（candidate）不落库**：AI 输出先进前端草稿/预览，作者确认后才写库；
2. **证据链（evidence）**：章后检查必须引用"章节 + 版本 + 字符区间 + 原文引用 + 内容哈希"；
3. **软删除 + 影响分析**：删除前 `delete-impact` 统计下游引用（篇章/场景/章/伏笔/记录），
   支持 `restore` 与 `hard`（硬删需无保护引用）。

## 4. 创作主流程：6 阶段状态机（界面驱动核心）

真实实现见 `frontend/src/components/writing/WritingFlowProgress.tsx`，它**不看用户点过什么，只看已保存的事实**，用固定顺序推断"下一步"，给出一个可点击的 href：

| phase | 阶段 | 判定条件（按顺序，第一条命中即当前步） | 目标 workspace |
| --- | --- | --- | --- |
| 0 | 建立作品 | 小说资料未保存 | `novel-info` |
| 1 | 开场资料 | `core_factions` 数量为 0 → 势力卡 | `faction-cards?view=profiles` |
| 1 | | `protagonist` 为 0 → 角色卡 | `character-cards?view=profiles` |
| 1 | | 无角色关系且未跳过 → 角色关系（**可跳过**） | `character-cards?view=relations` |
| 1 | | 无世界规则且未跳过 → 规则（**可跳过**） | `rule-cards` |
| 1 | | 无物品且未跳过 → 物品（**可跳过**） | `item-cards` |
| 2 | 本卷剧情 | 一卷都没有 → 准备第一卷 | `volume-planning?view=overview` |
| 2 | | 某卷 `plot_status != ready` → 完善该卷剧情 | `volume-planning?view=overview&volume_id=…&focus=plot` |
| 3 | 本卷准备 | `preparation.factions / characters / locations` 任一未就绪 | `volume-planning?view=factions|characters|locations&volume_id=…` |
| 4 | 本卷章节 | 无篇章 → 准备章节 | `arc-planning?volume_id=…` |
| 4 | | 篇章剧情未 ready | `arc-planning?volume_id=…&arc_id=…&focus=plot` |
| 4 | | 篇章下无场景 / 场景下无章 → 章节规划 | `chapter-editor?volume_id=…&arc_id=…[&scene_id=…]` |
| 4 | | 第一个 `word_count==0` 的章 → 写作 | `chapter-editor?...&chapter_id=…` |
| 5 | 检查或继续规划 | 已规划章节全部写完 | `chapter-editor` |

配套的**初始化门禁**（后端 `initialization_readiness_service`）固定 7 步，返回每步 `state(not_started/in_progress/ready/blocked)` 与 `count`：
`novel_profile → core_factions → faction_relations → protagonist → core_characters → character_bindings → character_relations`，
最后给出 `ready_for_world_and_volume`——**只有它为真，才允许生成世界规则与分卷**。这是"防跳步"的硬门禁。

> 设计亮点值得直接借鉴：**进度不是复选框，而是从数据重算**。用户手工补一条数据，进度自动前进；删掉数据，进度自动回退；"可选项"用 localStorage 记录"我选择跳过"，不污染服务端事实。

## 7. 关键机制（做同类产品可以直接复用）

| 机制 | 实现要点 | 价值 |
| --- | --- | --- |
| **候选审阅制** | AI 只产出 candidate + basis（生成输入快照），前端草稿存 localStorage，`confirm` 才落库 | 不污染正式数据、可反复比对 |
| **事实 vs 设计** | 角色/关系/物品都有"设计"字段与"事实"历史；章后检查产出事实候选 | 长篇不失忆、可回溯 |
| **证据链** | `evidence{chapter_id, version, revision_id, content_hash, start, quote}` | 任何自动改动都能定位原文 |
| **乐观锁** | 每实体 `version`，写请求带 `expected_version` | 多标签页/多次生成不打架 |
| **可编辑 AI 流程** | 节点图 + 端口 schema + preview 预演 + 内置方案哈希校验升级 | 用户可换模型、改提示词、加条件分支 |
| **Provider 抽象** | openai / deepseek / gemini / claude 四类适配器，能力开关（streaming / json_schema / function_calling）自动探测 | 换服务商零改代码 |
| **流式 SSE** | 生成任务同时提供同步与 `/stream`，事件 progress/step/done/error | 长篇生成体验 |
| **文件迁移** | `user_data/` 布局版本、任务流程修订版本、迁移失败保留现场 | 升级不丢数据 |

## 9. 工作界面流设计（本次交付）

把上面的事实抽象成"屏幕 + 状态迁移"。每个屏都标了**数据来源接口**和**可执行动作**，可以直接当开发任务清单。

```
 S0 书架 ──新建──▶ S1 新建小说（手工）──┐
   │                    └─ AI 创作（4 步流）─┤
   │                                        ▼
   └──────────打开书──────────────▶ S2 写作台外壳
                                          │
        ┌─────────────────────────────────┼──────────────────────────────────┐
        ▼                ▼                ▼                ▼                 ▼
   S3 小说信息      S4 开场资料      S5 本卷规划      S6 层级规划      S7 章节写作
   (phase 0)      (phase 1)        (phase 2-3)      (phase 4)        (phase 4)
        │                │                │                │                 │
        │          势力卡/角色卡/    卷概览 + 本卷     篇章 → 场景 →     正文编辑器
        │          关系/归属/规则/   剧情 + 势力/人物/  章计划三层树       + 章计划 + 资料
        │          物品（可选）      地点准备                            + 版本历史
        │                │                │                │                 │
        └────────────────┴────────────────┴────────────────┴─────────────────┘
                                          ▼
                              S8 章后核查（phase 5 之后）
                              心理状态 / 物品持有人 / 人物关系 / 世界规则疑点
                              每条都能"采用→写入事实"或"作废"（带证据）
                                          ▼
                              S9 继续规划 / 下一卷（回到 S5）
```

常驻层：**顶部创作进度条**（6 阶段 + 下一步提示 + "点击继续"）、**右侧 AI 候选抽屉**（生成中流式进度 → 候选对比 → 采用/编辑/重生成）、**资料变更广播**（任何保存都通知助手与图谱刷新）。

原型文件 `工作界面流原型.html` 已实现：S0–S9 全部屏幕、候选抽屉、进度跳转、关系图谱与章后核查的交互，并内置"流程地图"弹窗（把 §4 状态机与 §5 任务链画在一张图上）。

### 9.1 每个屏幕的要素清单（开发用）

| 屏 | 必须有的元素 | 关键交互 | 接口 |
| --- | --- | --- | --- |
| S0 书架 | 书卡（封面/标题/类型/进度/字数）、新建入口、已删除入口 | 打开、导出、软删 | `GET /api/novels/list` |
| S1 新建 | 创意输入、章节数/每章字数、AI 四步进度、候选预览、封面 | 开始/重试失败步骤/保存 | `POST /api/llm/create-novel-by-ai`、`POST /api/novels/create` |

| S4 开场资料 | 势力卡/角色卡/关系/归属/规则/物品，各带"生成"按钮 | 生成→勾选→保存、跳过可选 | 见 §6 对应分组 |
| S5 卷规划 | 卷列表、概览（剧情/势力/人物/地点四 tab）、目标字数/章数 | 生成全书分卷、完善本卷、确认 | `volumes/*`、`plan_volume_launch_by_ai` |
| S6 层级规划 | 卷→篇章→场景→章 树、每层 plot/planning 编辑 | 逐层生成、拖动排序、确认 | `arcs/*` `scenes/*` `chapters/*` |
| S7 章节写作 | 三栏：目录 / 正文编辑器（字数、保存、草稿）/ 右侧资料与检查 | 生成正文、续写、保存、历史版本 | `POST /api/llm/…/writing`、`chapters/{id}/content/confirm` |

| S9 助手 | 对话、变更审阅（apply/undo/review）、定位跳转 | 采用改动 | `novels/{id}/assistant/*` |
