# 墨脉 InkFlow · 长篇小说创作工作流

一套**可在本地运行**的长篇小说自动创作流水线（Arena Skill）：左侧是 16 个环节的工作流，右侧是完整的书。

选题 → 查重 → **世界观（力量体系 / 规则边界）** → 人物关系 → 分层大纲（L1/L2/L3）→ **节奏曲线检查** →
伏笔与钩子 → **逐章写作** → **三视角审稿**（逻辑审 / 读者审 / 编辑审）→ **修正** → **去 AI 味** → 定稿 →
**滚动摘要压缩（断点续写）** → 导出。

每一章都必须过 5 道硬闸门：**字数 > 2000、AI 味 ≤ 阈值、章末钩子 ≥ 6、伏笔执行、设定不冲突**。

- 零第三方依赖，`Node >= 20`，`npm start` 即用
- 默认内置**离线演示引擎**：不填 API Key 也能把全流程跑通（含真实的度量、报警、审稿报告）
- 填上任意 OpenAI 兼容网关 / Anthropic 的 Key，即切换为真实模型写作
- 数据全部落在本地 `data/`（JSON），可备份、可回滚、可换机续写

> 灵感来自 [YILING0013/AI_NovelGenerator](https://github.com/YILING0013/AI_NovelGenerator) 的分卷/分章/角色/伏笔数据模型；
> 本项目补齐了它的三个缺口：**世界观作为审核基准**、**每章多闸门审稿团**、**可观测的节奏曲线**。

## 快速开始

```bash
# 需要 Node.js >= 20（无需 npm install，零依赖）
npm start
# → http://localhost:5173
```

首次启动会自动生成一个 12 章的演示项目《照影·长明灯与影子》，含完整世界观、7 人物关系网、
12 章大纲、节奏曲线（含 2 个真实报警）、9 条伏笔台账，以及**已经过三审 + 修订 + 去 AI 味**的正文。

```bash
node scripts/seed.mjs --reset     # 重建演示项目（默认跑满全书，停在导出前）
npm run check                     # 引擎自检（25 项：计字/AI味/钩子/事实核对/查重/节奏/闸门/压缩）
```

### 导入自己的稿子（人写 + 机器审）

mock 引擎只会生成演示书；如果你手里的稿子是自己（或别的模型）写的，用导入脚本把它塞进流水线，
照样能跑本地三审、闸门、伏笔核对和导出：

```bash
node scripts/import.mjs 小说资料/十七秒 --reset       # 书籍目录 → 项目
node scripts/submission.mjs <projectId>             # 生成投稿包 + 全本样章
```

目录约定：一本一个文件夹——`小说资料/<书名>/书稿.json`（设定 + 大纲）、`正文.txt`（正文）。
章节在 txt 里用「第1章　标题」单独一行开头，脚本会自动切开。

### 接真实模型

界面右上角「设置」里填，或用环境变量：

```bash
# OpenAI 兼容（OpenAI / DeepSeek / Moonshot / 通义 / vLLM / Ollama…）
export LLM_PROVIDER=openai
export OPENAI_API_KEY=sk-...
export OPENAI_BASE_URL=https://api.openai.com/v1
export OPENAI_MODEL=gpt-4o-mini

# 本地模型（Ollama）
export OPENAI_BASE_URL=http://localhost:11434/v1
export OPENAI_MODEL=qwen2.5:14b
export OPENAI_API_KEY=ollama

# Anthropic
export LLM_PROVIDER=anthropic
export ANTHROPIC_API_KEY=sk-ant-...
export ANTHROPIC_MODEL=claude-sonnet-4-5
```

Key 只写入本机 `data/settings.json`（已在 `.gitignore` 中），不会进 Git。

## 全文审核（每写完一批就跑一遍）

```bash
npm run audit          # = node scripts/audit.mjs 小说资料/十七秒
npm run style          # 只看文笔画像：五感密度 / 短段占比 / 对话轮 / 解释句 / 开篇三件套
```

按 `docs/全文审核清单.md` 的五组口径查 42 项，**不依赖模型自评**，全部是本机确定性判定：

- **结构**：章号连续、每章 ≥2040 字、标题与大纲一致、大纲「转折」是否真写了、完稿进度
- **语言**：**AI 味 ≤1**、句长标准差 ≥6、对白占比 12%–60%、套话计数、**跨章重复句（≥12 字）**、标点（只用全角、对话用双引号 “”、引语内用 ‘ ’、破折号 0 处、省略号 ……）、**多音字出表**
- **逻辑**：设定冲突（`factCheck`）、**人名错字**（苏主/沈听兰这类）、日期与编号格式、伏笔到期未回收
- **体验**：章末钩子 ≥6、连续三章低密度报警、全书至少一章密度 5
- **文笔质感**：五感密度 ≥18/千字、短段占比 ≥50%、解释句 ≤4%、开篇三件套（台词/动作/异常）——口径与证据见 `docs/网文头部文笔拆解.md`
- **句子层**：超 45 字长句 ≤3%、弱动词 ≤2/千字、一句三个「的」≤6%、连词 ≤8/千字、被动 ≤6/千字、句首状语 ≤5%、名词化 ≤5/千字——口径见 `docs/句子级写法.md`，`npm run style -- --sentences` 单独看

结果写进 `小说资料/<书名>/审核报告.md`：逐章指标表 + 阻断/警告清单 + 改法。加 `--strict` 时有阻断项就退出码 1，可以直接挂 CI。

## 示例：为喜马拉雅活动写的《十七秒》

仓库里带了一个完整的真实案例，用来验证「活动调研 → 立项 → 成书 → 投稿包」整条链路：

- `docs/喜马拉雅有声小说活动与投稿方案.md`——2026 年在征集期内的三个官方活动、各自的考核口径、投稿包清单
- `小说资料/十七秒/`——24 章大纲（4 卷）、6 人设定、10 条伏笔台账、已完稿 21 章（45342 字）
- `小说资料/十七秒/正文.md`（可直接阅读）与 `正文.txt`——纯文本正文（章节标题单独成行，可直接发编辑或用手机看）
- `小说资料/十七秒/投稿包.md`——一句话简介 / 200 字简介 / 人物小传 / 24 章目录 / 第 1 章全文 / 质量自检表
- `小说资料/十七秒/有声化说明书.md`——角色音色表、每章场景声、音效点、制作规格
- `小说资料/十七秒/审核报告.md`——全文审核结果（逐章指标 + 阻断/警告）
- `小说资料/十七秒/朗读注音表.md`——多音字读音表（单独成文件，**不写进正文**）
- `docs/全文审核清单.md`——审核口径：查什么、阈值多少、谁来做

实测（本地确定性脚本）：21 章全部通过 5 道闸门，另有九类语病规则（重复虚词、口误用词、「通过…使…」等）逐章扫描，三审均分 97，**AI 味 0**（本书按 ≤1 的严口径执行），平均 2090 字/章，钩子最低 6.3。

## 需求对照

| 你提的要求 | 落点 |
|---|---|
| ① 方向选题（热度 + 创新性） | 环节 2-3：市场雷达打分 + 5 个不同情绪引擎的候选 + `heat*0.3 + novelty*0.4 + (100-risk)*0.3` 排序 |
| ② 查重（设定 / 情节） | 环节 4：本地语料 2-gram 余弦预计算 + 模型语义比对，输出重合维度与「必须修改项」；`duplicate` 会阻断流程 |
| ③ 大纲创作（分层 + 逻辑连贯） | 环节 7：L1 卷 / L2 弧 / L3 章，每章 `goal-obstacle-turn-result` 四段式，附因果链自检 |
| ④ 伏笔与钩子 | 环节 9：伏笔台账（布置章 < 回收章、中途提示、风险）+ 每章钩子类型；审稿按台账逐条验收 |
| ⑤ 人物关系构建 | 环节 6：欲望/障碍/错误信念/秘密/转折/弧光/语感 + 双向关系边 + 冲突矩阵 + 关系网图 |
| ⑥ 正文写作 | 环节 10：喂 L3 卡片 + 硬规则 + 出场人物 + 滚动摘要 + 上一章结尾 + 本章伏笔任务，字数不足自动续写 |
| ⑦ 审核（逻辑 / 设定冲突 / 文风） | 环节 11：三视角审稿团 + 5 道脚本实测闸门（字数、AI 味、钩子、伏笔、设定） |
| ⑧ 修正 | 环节 12：按严重度合并意见 → 最小改动修订 → 重审（最多 `reviewRounds` 轮，仍不过则标记「待人工」） |
| ⑨ 去 AI 味 | 环节 13：模型改写 + 本地规则层（30+ 组套话、命定旁白、长句、破折号）+ 改前改后指标与替换记录 |
| 补充：**世界观构建** | 环节 5：力量体系的 **规则 / 代价 / 上限 / 例外** + 4-6 条「可审核的硬规则」+ 术语表 → 逻辑审的判定基准 |
| 补充：**节奏曲线检查** | 环节 8：按章冲突密度画曲线（左栏 SVG），连续 3 章 ≤2、高潮间隔 ≥7 章、开局过载、结尾失速、弧线中段塌陷五类报警，可一键调律 |
| 补充：**多视角审稿团** | 环节 11 拆成逻辑审（0.15） / 读者审（0.4） / 编辑审（0.25）三个独立 pass，各自输出问题与结论 |
| 补充：**断点续写摘要压缩** | 环节 14-15：每章摘要入库；每 30 章（可配）滚动压缩到 ≤1400 字，写作只喂「滚动摘要 + 最近 3 章 + 上一章结尾」 |
| 补充：**市场热度自动化** | 环节 2 + `scripts/market-refresh.mjs`（可挂 cron）+ `POST /market/input`（把 WebSearch 结果写进证据链） |
| 补充：每章都要审全部内容 | 五道闸门覆盖字数、文风文笔、AI 味、伏笔钩子、逻辑设定，任一不过不进定稿 |
| 补充：左侧看完整大纲 / 世界观 | 左栏「世界观 / 人物 / 大纲」标签渲染全量产物（不是摘要） |
| 补充：右侧完整小说可收起 | 右栏全书通读 / 单章专注 / 一键收起 |

### 五道硬闸门（脚本实测，模型无权覆盖）

| 闸门 | 怎么量 | 默认阈值 |
|---|---|---|
| 字数 | 汉字 + 英文词，不计标点 | `≥ max(2000, 单章目标×0.85)` |
| AI 味 | 套话密度 + 排比/命定旁白/破折号结构惩罚，归一到 0-10 | `≤ 4.5` |
| 章末钩子 | 疑问 / 威胁 / 反常细节 / 揭示动作 / 否定异常 / 具体人物 | `≥ 6` |
| 伏笔执行 | 本章应布置/回收的伏笔名称或关键细节必须出现 | 全部 |
| 设定一致 | 位阶/身份/术语/硬规则事实核对 + 逻辑审 | 无 high |

> 这样设计的理由：审核环节如果只问模型「这章好吗」，模型永远说好。把可测量的部分交给脚本，
> 模型只负责「为什么这是问题、怎么改」，闸门才关得上。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 环节契约、提示词清单、设置、项目列表、SKILL.md |
| GET/POST | `/api/projects` | 列表 / 新建（body 即 brief） |
| GET | `/api/projects/:id` | 全量项目（含 stats / overview） |
| POST | `/api/projects/:id/run` | `{mode:"step"\|"auto"}`，返回 **SSE**：`log / step / step-done / project / error / finished` |
| POST | `/api/projects/:id/stop` | 暂停自动连跑 |

## 常见问题

**Q：没有 API Key 能干什么？**
能跑通全部 16 个环节、看到真实的大纲/世界观/节奏报警/审稿报告/闸门数值/去 AI 味前后对比，并导出演示书。
离线正文由演示引擎生成（结构正确、可读但套路化），它主要用来验收流程与指标。

**Q：为什么字数、AI 味不让模型自己说？**
因为模型倾向于给自己打高分。`server/text.js` 是确定性实现，同一段文字永远得到同样的分；
模型只在「诊断与改法」上发挥作用。

**Q：30 章之后上下文怎么控制？**
写作提示词只有五块：L3 卡片、硬规则、出场人物、滚动摘要 + 最近 3 章摘要、上一章结尾 800 字。
每 30 章把旧摘要压成 ≤1400 字，因此上下文随章数增长是**有界**的（界面「质量」页显示实时估算 tokens）。

**Q：接真实模型时报「没有返回 JSON」或「结构不符合约定」怎么办？**
`server/llm.js` 只做一件事：剥掉 ```json 围栏再解析。模型返回散文就会在**当前环节报错停下**，
不会把半成品写进项目文件。人物与大纲两个环节还会额外校验结构——缺 `characters[]`、
或大纲缺 `volumes[].arcs[].chapters[]`，都会直接提示「请重试」而不是继续往下跑。
常见处理：把温度降到 0.6–0.8、确认模型单次能输出 ≥6000 tokens、或换一个 JSON 更稳的模型。

**Q：某一章写崩了怎么办？**
「审核详情」里能看到三个视角的完整意见与版本列表，可回滚到任意版本重跑审稿；也可以直接改
`data/projects/<id>.json` 的 `current` 后重跑 review。被标记「待人工」的章节会在列表里变红。

**Q：能商用吗？**
代码 MIT。正文与设定由你的模型生成，版权归你（请自行确认所用模型的服务条款）；查重只做相似度提示，不构成法律意见。
